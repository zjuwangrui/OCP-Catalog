## 1. 为什么需要这场会

"加密和归因"里的**加密**在本仓库有唯一解释——`manifest_signed`、`signature_algorithms`、`trust_profile.signature_alg` 三处字段已声明但零实现，补齐即可，无歧义。

**归因**有两种互不相干的解释，且两种在代码里都有对应物：

| 解释 | 代码中的对应物 | 要做的事 |
|---|---|---|
| **A · 商业归因** | `action_binding` 缺失归因字段；`ProvenanceRecord`（数据来源）与 activity `correlation_id`（调用链）两条链断开 | 设计可验签的归因凭证，7 周 |
| **B · 结果可解释性** | `catalogEntryMatchSchema.explain: z.array(z.string())` 已存在但内容随意 | 规范化 explain 内容，约 1 周 |

**两者共用「归因」二字，但工作量相差 7 倍，交付物无任何重叠。** 猜错的代价是整个计划作废。

## 2. 要问的一句话

> **这个归因的下游是谁在用——是财务做分账结算，还是算法做搜索质量分析？**

这句话不含技术术语，不需要对方了解 schema，且答案直接二选一。

**不要问**"归因是指 attribution 还是 explainability"——对方大概率会回答"都要"，等于没问。

---

## 3. 三种回答与对应动作

| 回答 | 判定 | 立即动作 |
|---|---|---|
| "财务 / 分账 / 谁带来的单" | **A1 成立** | 按 7 周计划推进，W1-T2 当天启动 |
| "看搜索准不准 / 为什么排这个" | **A1 不成立** | **停止本计划**，改做 `explain` 规范化，约 1 周，另行出方案 |
| "都要" / 说不清 | **待定** | 追问第 4 节的三个问题，用回答倒推 |

---

## 4. 「说不清」时的三个追问

这三个问题都不问"你要什么"，而问"你已有什么"——已有物比意图更可靠。

1. **现在有没有人在算佣金或分成？用什么数据算的？**
   → 有 → A。没有且没计划 → B。

2. **这个东西做完，是给外部商户看，还是内部看？**
   → 外部商户 → A（外部方需要能独立验证，这正是签名的意义）。内部 → 偏 B。

3. **如果一个商户说"这单不是你带来的"，现在拿什么反驳？**
   → 这是 A 的核心场景。对方能立刻理解这个问题，说明是 A；对方觉得这问题不相干，说明是 B。
