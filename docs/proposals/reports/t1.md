# T1 小报告

| 项目 | 内容 |
|---|---|
| 任务 | **T1** · 商业归因数据模型定稿 |
| 日期 | 2026-09-15 |
| 计划 | [商业归因链 · 两周实施计划](../ocp-attribution-2w-plan.md) 第 1 周 |
| 状态 | 完成判据达成 |

---

本周把「这单归谁」从一句没人能验证的说法，变成了一份第三方拿到就能离线判定的数据契约：产出归因规范、四份机读 JSON Schema，以及挂进现有 `ocp-schema` 的两个可选字段，凭证在 resolve 时签发、经多跳转发时**每一跳各自签名**（借了广告业 schain 的链结构，补上了它缺的那道签名，也就补上了它十年没解决的可伪造问题），商户成交后凭订单号回报核销，多张凭证争同一笔订单时按写死的 last-touch 规则裁出唯一赢家——规则成文的意义在于各方独立算得出同一个结果，否则对账必然出分歧。规范里每个字段都写明了「删掉它哪条检查做不成」，同时把五个想加但没有消费方的字段连同否决理由一起记下来，免得后面反复提；25 条回归断言已验证不含归因字段的旧请求与旧响应全部原样通过，`catalogQueryRequestSchema` 一行未动。下周做验签实现，其中三条规则 schema 表达不了、必须写进代码，漏掉任一条都会放过「格式完全合法但可伪造」的凭证，已在计划里单独标出交棒。
